# IoT Smart Farm Simulator

An interactive 3D showcase built in **Godot 4** (GDScript). You walk around a small modern
farm, inspect 19 virtual IoT devices and watch eight automation rules control the 3D world.
Three are core farm rules (irrigation, greenhouse ventilation and grow lighting). Five more use
common smart-home device types: HVAC/thermostat, shades, water valve and leak sensor, lock,
contact and motion sensors, floodlight, camera, smoke/CO alarm and siren.

> **Everything is simulated in-game.** There is no real hardware, MQTT, SmartThings account or
> internet connection. The device concepts and dashboard look are *inspired by* smart-home
> platforms such as Samsung SmartThings. This project is not affiliated with or endorsed by Samsung.

One shared project and codebase targets **PC (Windows/Linux/macOS)**, **mobile (Android/iOS)** and
**Web (WebGL 2 / WebAssembly)**.

## Opening and running

1. Start Godot 4.7, click **Import**, and select this folder's `project.godot`.
2. Press **F5** (Run Project). The game starts on `scenes/Boot.tscn` (a loading screen), which loads
   `scenes/Main.tscn`.

From the command line:

```bash
# run the game
godot --path .

# useful flags (after "--"):
godot --path . -- --skip-tutorial          # don't show the intro tutorial
godot --path . -- --quality=low            # force a graphics preset (low|medium|high)
godot --path . -- --touch                  # show touch controls on PC (mouse emulates touch)
godot --path . --resolution 390x844 -- --touch   # preview a phone layout
```

## Controls

| Action | PC (keyboard + mouse) | Touch (phones, tablets, mobile browsers) | Gamepad |
|---|---|---|---|
| Move | `W A S D` / arrow keys | Left virtual joystick | Left stick |
| Look | Click the view, then move the mouse (or hold right mouse button) | Drag on the right side of the screen | Right stick |
| Sprint | `Shift` (hold) | `SPRINT` button (toggle) | Left stick click |
| Jump | `Space` | `JUMP` button | A / Cross |
| Inspect device | `E` (or click the prompt) | `INTERACT` button or tap the prompt | X / Square |
| Dashboard | `Tab` | **Dashboard** button (top right) | Back / Select |
| Pause / close panel | `Esc` | **Menu** button / **X** | Start |

All input goes through `InputManager`. Gameplay code never reads devices directly.

## Virtual devices

| Device | Where | What it does |
|---|---|---|
| **Smart Farm Hub** | IoT control station (west path) | Central hub: connection overview, device list, automation count, "reconnect all" and "simulate outage". Automations pause while the hub is off. |
| **Soil Moisture Sensor** | Greenhouse, north bed | Simulates soil moisture. It dries faster when hot and rises while irrigating. The soil visibly darkens when wet. |
| **Temperature Sensor** | Greenhouse aisle | Simulates greenhouse air temperature and humidity (solar gain, cooling from fans). |
| **Ambient Light Sensor** | Pole at the control station | Daylight level from the day/night cycle. |
| **Smart Plug** | Next to the pump | Supplies power to the irrigation pump and reports its load in watts. |
| **Irrigation Pump** | Beside the water tank | Runs only when switched on **and** the plug is on. Spins its motor, pulses water along every pipe and drives 8 sprinklers (greenhouse + field). |
| **Ventilation Fans** | Greenhouse back wall | Two exhaust fans with animated blades. |
| **Greenhouse Grow Lights** | Greenhouse (wall switch by the door) | 8 LED fixtures with emissive panels and real lights. |

### Smart-home devices (climate, water, security, safety)

These follow the most common SmartThings device categories (capabilities). They are all simulated in-game.

| Device | SmartThings-style capability | Where | What it does |
|---|---|---|---|
| **Greenhouse HVAC** | Thermostat (mode, heating/cooling setpoint, operating state) | Heat-pump outdoor unit on the greenhouse's east side, indoor wall unit inside | Heat / Cool / Auto modes with setpoints (default Auto, heat to 18 °C, cool above 33 °C) and a 0.5 °C deadband. Heats the greenhouse on cold nights. Cooling is "stage 2" behind the exhaust fans. The outdoor fan spins, the indoor unit glows orange or blue, and energy use is metered. |
| **Greenhouse Shade Screen** | Window shade (open / close / position) | Under the greenhouse roof (switch left of the door) | Motorised cloth screen that slides across the roof. Closed, it blocks part of the solar gain. |
| **Main Water Valve** | Valve (open / closed) | On the irrigation main next to the pump | The pump can only deliver water while it is open. Its lever animates. |
| **Water Leak Sensor** | Water sensor (wet / dry) | On the ground under the irrigation main | Owns a simulated burst fitting. Water sprays, a puddle spreads, and the sensor goes wet. Has a "repair fitting" control. |
| **Shed Door Lock** | Lock + keypad | Utility-shed door | Locked/unlocked deadbolt that owns the real, animated door. A locked door can't be opened, and the bolt can't be thrown while the door is open. |
| **Shed Door Contact** | Contact sensor (open / closed) | Shed door frame | Reports the door state. Night lockdown relies on it. |
| **Yard Motion Sensor** | Motion sensor | Shed corner | **Detects you**: walking into its 8 m / 120° field of view triggers it. Stays active for 8 s after the last movement. |
| **Security Floodlight** | Switch | Above the shed door | LED floodlight (a real spotlight on Medium/High). |
| **Yard Security Camera** | Video camera + motion | Shed corner | **Live feed in the device panel**, with automatic night vision after dark. Records a clip whenever motion is detected. It only renders while someone is watching it. |
| **Smoke & CO Alarm** | Smoke + carbon monoxide detector | Control-station ceiling | Owns a simulated smouldering cable in the console: grey smoke rises, the alarm beeps and flashes, then clears on its own. |
| **Outdoor Siren** | Alarm (siren + strobe) | Control-station post | Two-tone siren with a rotating red strobe. |

Walk up to a device and a ring and prompt appear. Inspect it to see live readings and controls
(power, network connect/disconnect, hub actions). The dashboard also controls every device.

## Automation scenarios

| # | Rule | Trigger | Action |
|---|---|---|---|
| 1 | **Smart Irrigation** | Soil moisture **< 30 %** | Smart plug + pump **ON** → sprinklers, pipe flow, rising moisture. **OFF at 65 %**. |
| 2 | **Smart Temperature Control** | Greenhouse **> 32 °C** | Ventilation fans **ON**. **OFF below 28 °C**. |
| 3 | **Smart Lighting** | Ambient light **< 35 %** | Grow lights **ON**. **OFF at ≥ 40 %**. |
| 4 | **Smart Sun Shading** | Ambient light **≥ 80 %** | Shade screen **CLOSES**. **OPENS below 60 %**. |
| 5 | **Leak Protection** | Leak sensor **wet** | Main valve **CLOSED** and pump **OFF**. Reopens once the ground is dry **and** the fitting is repaired. |
| 6 | **Security Lighting** | **Motion** at the shed while ambient light **< 35 %** | Floodlight **ON**. **OFF after 30 s** without motion. The camera records the clip. |
| 7 | **Smoke Alarm** | Smoke/CO alarm triggered | Siren and strobe **ON**, shed door **UNLOCKED** (escape route). Siren **OFF** when the smoke clears. |
| 8 | **Night Lockdown** | Dusk (ambient light **< 35 %**) | **Locks the shed**. If the contact sensor says the door is open, it waits and locks as soon as the door closes. |

- Rules fire when a reading **enters** a zone, with hysteresis. Manual overrides between thresholds
  are respected.
- Each rule can be enabled or disabled in **Dashboard → Automations**. Disabling a rule switches off
  anything it started.
- Rules pause if the hub is off or a required device is disconnected.
- **Trigger scenarios** (Dashboard → Overview, or "Run scenario" on each card): *Simulate dry soil*,
  *Simulate heat wave*, *Jump to dusk*, *Jump to midday*, *Midday sun (shade)*, *Burst pipe fitting*,
  *Night intruder*, *Smoke in cabinet* and *Shed left open at dusk*.
- The HUD's **Security** chip summarises the most important alert (smoke, water leak, motion,
  shed open or unlocked), much like SmartThings' home-monitor status.
- The dashboard's **Devices** tab groups devices by category: Hub, Climate, Water & irrigation,
  Lighting, Security, Safety.
- One in-game day lasts 6 real minutes. The simulation speed can be set to pause, 1x, 4x or 12x.

## Running the automated tests

```bash
# 42 unit + integration tests, headless (exit code = number of failures)
godot --headless --path . res://tests/TestRunner.tscn

# write the report somewhere specific
godot --headless --path . res://tests/TestRunner.tscn -- --results=test_results.txt

# GUI smoke test: drives the real game (movement, camera, interaction, all eight
# automations, dashboard, pause, presets), saves screenshots, and prints PASS/FAIL lines
godot --path . --resolution 1920x1080 -- --autotest --skip-tutorial --shots=./shots

# responsive-layout screenshots only
godot --path . --resolution 390x844 -- --autotest --layout --touch --skip-tutorial --shots=./shots
```

Note: on a fresh clone, run `godot --headless --path . --editor --quit` once first so Godot
imports the project and registers the script classes.

See `TEST_REPORT.md` and `PLATFORM_TEST_REPORT.md` for the actual results.

## Exporting

`export_presets.cfg` has presets for **Windows Desktop**, **Web**, **Android** and **iOS**.
Install the Godot 4.7.2 export templates (Editor → Manage Export Templates), then:

```bash
godot --headless --path . --export-release "Windows Desktop" build/windows/IoTSmartFarm.exe
godot --headless --path . --export-release "Web" build/web/index.html
godot --headless --path . --export-debug  "Android" build/android/IoTSmartFarm.apk   # needs Android SDK + JDK in Editor Settings
```

### Web hosting requirements
- Serve the `build/web` folder over **HTTP(S)**. Opening `index.html` from disk does not work.
  For a quick local test, run `python -m http.server 8000` inside `build/web`, then open http://localhost:8000.
- The Web preset uses the **single-threaded** build, so no `Cross-Origin-Opener-Policy` /
  `Cross-Origin-Embedder-Policy` headers are required. Any static host works.
- Browser needs **WebGL 2** (current Chrome, Edge, Firefox, Safari 15+).
- Audio starts after the first click/tap (browser autoplay policy). Mouse look uses pointer lock,
  which starts when you click the game view.

### iOS
iOS export requires macOS with Xcode. The preset exports an Xcode project only.
